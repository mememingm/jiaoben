# 已开卡 eSIM 按 ICCID 准备手动写入

入口：`http://127.0.0.1:8765/installation.html`。此路径独立于新卡开户，不创建订单，不调用开户提交，也不替代设备上的安装客户端。

更新代码后需要重启本地服务才能使用新入口；仍在运行的旧服务不会自动加载新代码。

1. 在 Profile 状态页筛选 1—200 张 USED + RELEASED，点击“将筛选中的待安装卡带入”；或者在新页面直接粘贴 ICCID。
2. 输入平台账号密码，点击“只读核对 ICCID”。进度条先显示登录与读取库存阶段，再显示逐卡核对进度。后台重新登录，匹配当前组织的 USED 库存 ID，并读取专用 Profile 状态。未找到、重复、非 RELEASED、查看次数缺失/耗尽均逐卡显示，不静默删除。
3. 勾选可处理卡，点击“获取所选卡的安装资料”，明确确认后才请求安装资料。后台再次核对账号、库存与状态；每张请求前再检查一次 Profile。可处理是本地预检结论，不保证平台允许 USED 卡取回有效资料。
4. 成功后下载对应二维码 PNG 或 LPA 文本，由你手动在设备上下载安装。下载读取已经保存的本地文件，不重新调用平台。
5. 点击“安装后复查状态”，返回状态页并带入原 ICCID；填写账号密码后由用户发起查询。

## 本地保存和恢复

- `outputs/installation-batches/im-<随机编号>/record.json` 保存核对进度、账号归属和逐卡状态，不包含密码或 LPA。只读核对任务也会保存，以供历史记录恢复。
- 同批次的 `materials/<inventory_id>.txt` 与 `.png` 是安装资料，仅在用户明确获取后写入。它们含敏感激活信息，不应上传或共享。
- `outputs/installation-attempts/` 为平台、组织、库存 ID 建立统一请求标记；新开户、旧写卡入口与本流程共用标记，不能通过新建批次绕过。
- “历史记录”由本浏览器的受保护 Cookie 关联服务端任务索引；关闭浏览器后仍可打开先前任务。历史列表只返回任务状态、数量与首张 ICCID 尾号，不返回密码、LPA 或图片。清除本站 Cookie 会失去历史入口，服务端文件不会因此删除。
- 服务重启后可恢复已落盘核对记录与已保存资料的下载；中断任务不会自动继续。重启前核对通过、但未获取资料的历史任务只供查看，如需获取须重新只读核对。更新前已关闭标签页的旧任务不会自动加入新历史索引，仍可从服务端目录核查。
- 历史批次已有获取记录时，本流程会阻止再次获取，要求先核查已保存资料；未知结果不自动重试，也不自动删除标记。
- 单张出错后停止后续请求，尚未请求的卡保持明确标记。修正纯预检错误后可以重新核对；已经留下请求标记的卡仍会被拦截。

服务仍仅适合本机或有认证保护的受控环境。任务编号是访问该批次的随机凭证，不要分享任务 URL。本次实现通过离线合成数据验证，不代表已确认平台允许所有 USED 卡获取资料；没有执行真实获取或开户。
